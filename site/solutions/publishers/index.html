How budgets and the daily ceiling work

The policy

Allow the crawlers you want. Price the pages the rest want.

A publisher policy file

Verified search engines and monitoring pass first. Anything that is not a browser stops next. Pages carry a price, and the five-minute loop's answers act live: a cohort the decision model reads as content scraping gets a proof-of-work three times harder, and a risky session on an article is served your cheaper response.

  • degrade tells your app to serve a summary or a paywall instead of the full page.
  • AI agents that sign their requests with Web Bot Auth are verified before your rules run.
  • Every field here is in the policy reference.

botrampart.policy.yaml · publisher

path_classes:
  - { name: static, match: ["/assets/*", "*.css", "*.js"], cost: 0, min_tier: 0 }
  - { name: article, match: ["/news/*", "/docs/*"], cost: 4, min_tier: 0 }
  - { name: listing, match: ["/listings/*"], cost: 4, min_tier: 1 }
  - { name: search, match: ["/api/search*"], cost: 5, min_tier: 1 }
  - { name: prices, match: ["/api/prices*"], cost: 10, min_tier: 1 }
mint: { ip: 20, prefix: 60, asn: baseline_x5, ja4: baseline_x5 }
risk_score:
  - { when: "signals.no_input_after_30_requests", add: 3 }
  - { when: "signals.automation_flag", add: 4 }
  - { when: "net.asn_class == 'hosting'", add: 2 }
rules:
  - { id: verified-bots, when: "net.verified_bot in ['search_engine', 'monitoring']", then: allow }
  - { id: not-a-browser, when: "!ua.is_browser || ua.browser_age_years > 3", then: block }
  - id: scrape-cohort
    when: "ai.intent == 'content_scraping' && ai.confidence >= 0.7"
    then: "pow(3)"
  - id: risky-reader
    when: "risk.score >= 5 && request.path_class == 'article'"
    then: degrade
  - { id: risk-5, when: "risk.score >= 5", then: "challenge(human)" }
  - id: over-budget
    when: "session.credits < request.cost"
    then: "challenge(next_tier) || throttle"
  - { id: default, when: "true", then: allow }

Questions from publishers

Before the crawlers come back.

Do search engines still index us?

Yes. The first rule allows verified search engine and monitoring crawlers, and verification does not trust the user-agent string, so a scraper that calls itself a search engine meets the not-a-browser rule instead.

Can we let some AI agents in and keep others out?

Agents that sign their requests with Web Bot Auth are verified before your rules run. Allow the ones you have an agreement with, and give them a budget of their own with allow(budget: agent).

What about a scrape spread across thousands of residential addresses?

Each session stays under budget, so no single request gives it away. The five-minute loop sees the cohort spend climb against its own baseline, and two windows that agree, 10 to 15 minutes, raise its price.

Do readers who arrive from search get challenged?

No. A first article fits in the 30-unit provisional allowance, the proof-of-work runs in the background, and at one page a minute a reader's budget refills faster than they spend it.
