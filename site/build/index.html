Build · 01 · getting started

Watch first. Enforce later.

One generator, one container, two lines in your app. Observe mode decides every request, logs it and lets it through, so you see what BotRampart would have done before it does anything.

What you need

  • A Node app on Express, Fastify or Next.js.
  • Somewhere to run Core: a Cloudflare account (Workers Paid starts at $5 a month{{c:cf-workers-price}}) or any host that runs one container. Recommended: 256 MB of memory. No database server.
  • An S3-compatible bucket: Cloudflare R2, Amazon S3, or MinIO, which the generator can bundle.
  • Optional: a key for a decision-model provider, or a self-hosted model. Without one, the five-minute loop is off and everything else works.

  1. Generate the install

    The generator asks four questions and writes plain files you can read and commit. It generates your site keys locally and sends them nowhere.

    The four questions

    ? Where will Core run?      Cloudflare | Docker on a Linux host | Kubernetes
? Object storage?           R2 | S3 | MinIO (bundled)
? Where are access logs?    nginx | ingress-nginx | ALB | none yet
? App framework?            Express | Fastify | Next.js
✓ wrote docker-compose.yml, botrampart.policy.yaml
✓ generated site keys into ./secrets (never sent anywhere)

    On Cloudflare it writes a Wrangler configuration and a deploy button instead of a compose file. Kubernetes gets plain manifests.

  2. Start Core

    Core is one small service. It reads where the lake is and which decision model to use from its environment, and its keys from the secrets the generator wrote.

    Core's environment

    BR_LAKE_URL=s3://acme-botrampart/br/v1/
BR_DECISION_PROVIDER=off        # or gemini, openai, a self-hosted model

  3. Add the backend SDK, in observe mode

    Mount the SDK at the root of your app so every route gets a path class by default. In observe mode it decides every request and logs the decision, but lets everything through.

    server.js · Node, ExpresssyncInstance

    import express from "express";
import { botrampart } from "@botrampart/node";

const app = express();
const br = botrampart({
  site: "site_123",
  secretsFile: "./secrets/br_keys",
  core: "http://localhost:8787",   // counters sync here every 5 to 10 seconds
  mode: "observe",                 // decide and log, enforce nothing
});
app.use(br.express());             // mounts /_br/*, verifies, charges, sets req.br

  4. Add the browser SDK

    One script tag, served from your own origin by the backend SDK, so no third-party domain can change the code your visitors run. That is the lesson of the 2024 Polyfill.io incident, when a CDN script under new ownership served malware to more than 100,000 sites.{{c:polyfill}}

    Your page templategetSdkScript

    <script src="/_br/sdk.js" data-site="site_123" async></script>

  5. Check the install

    Open your site and ask the SDK what the browser holds. A first visit is tier 0; a moment later the proof-of-work has run in the background and the session is tier 1.

    In the browser, from your own origingetSessionStatus

    await fetch("/_br/status").then((r) => r.json());
// { "tier": 1, "expiresAt": 1794825300, "sessionEndsAt": 1795428300, "tierExpiresAt": {}, "identified": false }

  6. Watch for an hour

    Within the first hour the decision log in your bucket shows spend by path class, the sessions that would have been challenged and why, and path costs suggested from how long each path takes to answer. Try a draft policy against that traffic before you enforce anything:

    Replay a draft against the last 24 hourssimulatePolicy

    curl -X POST "http://localhost:8787/v1/policy/simulate" \
  -H "Authorization: Bearer $BR_CONSOLE_TOKEN" -H "Content-Type: application/json" \
  -d @draft-policy.json

{ "challenged_share_current": 0.004, "challenged_share_draft": 0.012, "signed_in_affected": 0,
  "summary": "Would have challenged 1.2% of sessions against 0.4% today, none of them signed in." }

  7. Enforce tier 1

    Switch mode to "enforce" with the default policy. Ordinary browsing stays inside the refill rate and sees nothing. Clients that cannot run JavaScript keep reading general pages on their 30-unit allowance and are asked for a proof-of-work on costly paths. Keep the five-minute loop in shadow until its answers match what you would have done.
